# system

Host-side pieces installed onto the target machine: privileged wrapper scripts, the sudoers drop-in, systemd units/timers, the install script and the Docker socket proxy's allow-list. See `CLAUDE.md` in this folder for the rules — all changes here are review-required.

- `docker-socket-proxy/haproxy.cfg` — the only Docker API requests the app can make (read-only; on the official HAProxy image). Used by `dev/compose.dev.yml` now; by the app's production stack later.

- `wrappers/` — the four root wrappers, each a thin entry (`laris-compose.mts`, `laris-backup.mts`, `laris-disk.mts`, `laris-process.mts` — the files sudoers names) over its modules: `lib/` (shared by the wrappers, never by the app: output and markers, start-up, input, path rules, the shared lock), `compose/`, `backup/`, `disk/` and `process/` (one module per concern). Every module runs as root, so **the whole folder** is installed root-owned and writable only by root (`/opt/laris/libexec/`); each entry checks that before loading any module, and refuses to start otherwise (`wrappers/entry.spec.ts`).
- `wrappers/laris-compose.mts` — the deploy wrapper: installs and removes catalog services with `docker compose` (TypeScript run by Node, zero dependencies). Installed root-owned as `/opt/laris/libexec/laris-compose.mts`. Tests: `wrappers/laris-compose.spec.ts` (run by the server's unit tests).
- `wrappers/laris-backup.mts` — the backup wrapper: Borg backups of the platform, services and chosen folders to a disk under `/mnt` or `/media`; restores; the repository and its passphrase (from `eff_large_wordlist.txt`, the unchanged EFF list — installed beside it, root-owned). Installed as `/opt/laris/libexec/laris-backup.mts`; run by the app through sudo and by the timers below. Tests: `wrappers/laris-backup.spec.ts` (fake `borg` and `docker` in `wrappers/testing/`) and `wrappers/laris-backup.borg.spec.ts` (the real Borg, skipped without it). Design: `docs/plans/backups.md`.
- `wrappers/laris-disk.mts` — the disk wrapper: mounts a disk at `/mnt/<name>`, kept after a restart with its own systemd unit `/etc/systemd/system/mnt-<name>.mount` (not a line in `/etc/fstab` — `systemctl list-units --type=mount` lists them; `nofail`, so a missing disk never delays the boot), and unmounts the ones it mounted. Refuses every partition of the system's disk, anything mounted, swap, RAID/LVM/encrypted members and filesystems other than ext4, xfs, btrfs and exFAT — read again from `/sys`, udev's database and mountinfo. Installed as `/opt/laris/libexec/laris-disk.mts`. Tests: `wrappers/laris-disk.spec.ts` (a pretend host and a fake `systemctl`). Design: `docs/plans/disk_management.md`.
- `wrappers/laris-process.mts` — the process wrapper: sends SIGTERM or SIGKILL to a person's process (`signal`). Only a person's: every uid of its owner from 1000 to 60000 and none the app's own (`process.appUid` in `wrappers.json`, required as root); never PID 1, a kernel thread or a process in a container. PID and start time must both match (a PID used again is refused), read again from `/proc`. It takes on the owner's uid and gid before signalling, so it never signals anything as root. Installed as `/opt/laris/libexec/laris-process.mts`. Tests: `wrappers/laris-process.spec.ts` (a pretend `/proc`, and a real child process). Design: `docs/plans/process_list.md`.
- `sudoers/laris` — the `/etc/sudoers.d/` drop-in: the app's user may run exactly those four wrappers as root.
- `systemd/laris-backup.{service,timer}` — scheduled backup runs (the wrapper directly, never through the app); the chosen schedule replaces `OnCalendar` through a drop-in `laris-backup configure` writes. `systemd/laris-backup-now@.service` — "Back up now" (`laris-backup start` starts it, so the run doesn't belong to the app). `systemd/laris-backup-check.{service,timer}` — the weekly repository check (monthly with all data read back).
- `config/wrappers.json` — an example of `/etc/laris/wrappers.json` (root-owned): the catalog folder, storage roots, reserved ports, platform folders, the docker binary; under `disk`, systemctl; under `backup`, Borg and systemctl, the app's user and group, and the platform's database container and files.

Root-owned state the backup wrapper keeps: `/etc/laris/backup.json` (the plan), `/etc/laris/backup-repository.json` (the repository's path and id), `/etc/laris/backup.passphrase` (0400), `/var/lib/laris/backups/` (0750 root:app group — `runs.jsonl` and `current.jsonl` are 0640, readable by the app; Borg's cache and the set-aside list are root-only), `/srv/laris/restores/`.

Design: `docs/plans/service_deploys.md`, `docs/plans/backups.md`. `install/` is still empty (the installer feature).

- `install/` — the installer (`install.sh`, run from the release archive as `sudo ./install.sh`; its parts in `install/lib/`: checks, packages, files and settings, the platform and database), `tmpfiles.conf` (the proxy's socket folder in `/run/laris`, made again at every boot) and `laris-setup-code`. Design: `docs/plans/installer.md`. Tested by `tools/vm/test-install.sh`.
- `platform/compose.yml` — the platform's own containers: Postgres (127.0.0.1 only) and the Docker socket proxy (no network: a Unix socket in `/run/laris/proxy`). Started by `systemd/laris-platform.service`; the app itself is `systemd/laris.service`.
