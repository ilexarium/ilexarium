# system

Host-side pieces installed onto the target machine: the helper and the root programs, systemd units and timers, the installer and the Docker socket proxy's allow-list. See `CLAUDE.md` in this folder for the rules — all changes here are review-required.

The app holds no root and no sudo rule (`docs/plans/acting_as_you.md`): changes run as the signed-in person's Linux account, root work through that account's own sudo.

- `docker-socket-proxy/haproxy.cfg` — the only Docker API requests the app can make (reads, and start/stop/restart of a container; on the official HAProxy image).

- `programs/` — TypeScript run by Node with zero dependencies, each a thin entry over its modules: `lib/` (shared by the root programs, never by the app: output and markers, start-up, input, path rules, the shared lock), `helper/`, `backup/` and `disk/`. **The whole folder** is installed root-owned and writable only by root (`/opt/ilex/libexec/`); each entry checks that before loading any module, and refuses to start otherwise (`programs/entry.spec.ts`). Tests run with the server's unit tests (fakes in `programs/testing/`); the rules both sides write are compared in `programs/rules-match-app.spec.ts`.
- `programs/ilex-helper.mts` — runs **as the person**, one per Linux session, in an SSH channel of its own: JSON requests for a fixed list of actions — who it is, sudo unlock, signals, Docker access, app tasks (`docker compose` as systemd units: the person's own, or a system unit through their sudo), Compose checks, folder sizes and removal, and the root programs. No shell. Tests: `programs/ilex-helper.spec.ts`. Design: `docs/plans/acting_as_you.md`.
- `programs/ilex-root.mts` — runs **as root**, started by the person's sudo when they unlock it, for the unlock (15 minutes after its last action at most): the helper's privileged actions, forwarded to it. Tests: `programs/ilex-root.spec.ts`, and the helper's. Design: `docs/plans/ilex_root.md`.
- `programs/ilex-backup.mts` — root: Borg backups of this app, of apps (their folders, as Docker shows them) and of chosen folders to a mounted disk; restores as their own unit (`ilex-restore@<id>.service`), back where they were or into any folder; the repository and its passphrase (from `eff_large_wordlist.txt`, the unchanged EFF list). Started by the person's sudo through the helper, and by the timers below. Tests: `programs/ilex-backup.spec.ts` (fake `borg` and `docker`) and `programs/ilex-backup.borg.spec.ts` (the real Borg, skipped without it). Design: `docs/plans/backups.md`.
- `programs/ilex-disk.mts` — root: mounts a disk at a folder outside the system's own, kept after a restart with its own systemd mount unit (`nofail`), its top folder given to the person when asked; unmounts the ones it mounted. Refuses every partition of the system's disk, anything mounted, swap, RAID/LVM/encrypted members and filesystems other than ext4, xfs, btrfs and exFAT. Tests: `programs/ilex-disk.spec.ts` (a pretend host and a fake `systemctl`). Design: `docs/plans/disk_management.md`.
- `systemd/ilex-backup.{service,timer}` — scheduled backups (the program directly, never through the app); the schedule is a drop-in `ilex-backup configure` writes. `ilex-backup-now@.service` — "Back up now". `ilex-backup-check.{service,timer}` — the weekly repository check. `ilex-restore@.service` — one restore. `ilex.service`, `ilex-platform.service` — the app and its platform containers.
- `config/wrappers.json` — an example of `/etc/ilex/wrappers.json` (root-owned, the installer writes it): protected folders, the docker binary; under `disk`, systemctl; under `backup`, Borg and systemctl, the app's user and group, and the platform's database container and files.
- `install/` — the installer (`install.sh`, run from the release archive as `sudo ./install.sh`; its parts in `install/lib/`), `sshd.conf` (passwords from localhost only), `tmpfiles.conf` (the proxy's socket folder in `/run/ilex`) and `ilex-setup-code`. Design: `docs/plans/installer.md`. Tested by `tools/vm/test-install.sh`.
- `platform/compose.yml` — the platform's own containers: Postgres (127.0.0.1 only) and the Docker socket proxy (a Unix socket in `/run/ilex/proxy`).
- `backup-recovery.md` — bringing everything back on a new machine.

Root-owned state the backup program keeps: `/etc/ilex/backup.json` (the plan), `/etc/ilex/backup-repository.json` (the repository's path and id), `/etc/ilex/backup.passphrase` (0400), `/var/lib/ilex/backups/` (0750 root:app group — each job's file in `jobs/` (a run, a check, a restore; the newest 500 kept) is readable by the app; Borg's cache and restore requests are root-only).
